# 0010: 二进制文档（PDF/Word）轻量解析与内嵌图片 Markdown 打桩规范

## 背景与问题
在团队与企业生产环境中，大量核心资产以 PDF 与 Word (.docx) 二进制格式存在。若仅做纯文本抓取，不仅丢失排版结构，还会将文件内部关键的技术架构图、流程图和数据报表永久丢弃；若引入重量级 OCR 或庞大的外部文档解析框架，会造成数 GB 的环境体积膨胀与部署困难。

## 架构决策
决定采用纯 Python 轻量解析与就地图片打桩管道：
1. **轻量纯 Python 依赖**：选用 `pypdf` 与 `python-docx`，作为可选 extras 依赖（`[office]`），坚守零外部 C++ / Poppler / LibreOffice 的跨平台纯净性；
2. **内嵌图片无损解包**：从 Word 压缩包（`word/media/`）与 PDF 页面对象流中提取有效插图，并持久化至知识库资产目录 `data/assets/{kb_name}/{doc_id}/`（或 S3 存储桶）；
3. **噪点清洗门禁**：在内存中快速过滤分辨率小于 100 像素或体积小于 5KB 的微型图元（页眉 Logo、小图标、分割线）；
4. **正文就地打桩（Anchor Injection）**：在提取文本的对应上下文位置插入标准 Markdown 图片引用（`![文档插图](rag://assets/...)`），直接将二进制多模态文档降维归一化为通用 Markdown 图文流，完整复用后续切片保护、向量注入与 MCP Resource 团队分发通道。
